# Packaging

Three AUR packages, mirroring the split:

| Package | Ships | Depends on |
|---|---|---|
| `penguinwave-daemon` | `penguinwave-daemon`, `penguinwave-cli`, systemd user unit, udev rule, completions | `pipewire`, `hidapi` |
| `penguinwave` | `/usr/bin/penguinwave`, `.desktop`, icons | `penguinwave-daemon`, webkit/GTK |
| `penguinwave-bin` | the same, from the release `.deb` | `penguinwave-daemon`, webkit/GTK |

`penguinwave-daemon` carries no webview or GTK dependency, so it installs and
runs on a headless machine.

## The unit is not enabled by the package

User units are per-user and package scripts run as root, so `post_install` can
only tell the user what to run. The desktop app offers a button instead, since
it knows which user is in front of it. `scripts/check-packaging.sh` fails the
build if a package script ever tries to enable it.

## Files

| File | Installed to |
|---|---|
| `penguinwave.service` | `/usr/lib/systemd/user/penguinwave.service` |
| `99-penguinwave.rules` | `/usr/lib/udev/rules.d/99-penguinwave.rules` |
| `com.penguinwave.app.desktop` | `/usr/share/applications/` |
| `icons/` | `/usr/share/icons/hicolor/` |

The udev rule ships only with `penguinwave-daemon`: it grants HID access and
HID is the daemon's concern. Installing it from two packages would be a file
conflict, which the packaging check also guards.

Completions are generated by the binary during `package()`, so they cannot
drift from the commands they describe.

## Releasing

1. Bump `version` in the workspace `Cargo.toml`, `ui/src-tauri/tauri.conf.json`
   and every `PKGBUILD` — the check enforces they agree.
2. Tag `v<version>` and let the release build produce the `.deb`.
3. Replace the `SKIP` checksums with real ones (`updpkgsums`).
4. Regenerate `.SRCINFO` (`makepkg --printsrcinfo > .SRCINFO`).
